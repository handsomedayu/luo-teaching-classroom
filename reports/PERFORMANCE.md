# 优化前后性能实测

2026-10-17，Windows，同一台机器、Chrome 156.0.8078.35 headless，基线main `de6e6c5` 与当前分支。暂停其他浏览器回归后，先前版后新版交替运行3轮，取中位数。桌面1366×768，移动844×390（触控模拟）。每个场景连续播放3.6秒，再测6次翻页。采集真实浏览器CDP Performance指标和 `devtools.timeline` trace；没有使用虚拟时钟测性能。

| 场景 | 完整render调用（次，前→后） | 脚本耗时（ms，前→后） | 布局耗时（ms，前→后） | 按钮到两次rAF的p95（ms，前→后） |
|---|---:|---:|---:|---:|
| 物理焦耳热 / 桌面 | 78.0 → 6.0 | 48.0 → 80.0 | 51.5 → 110.3 | 9.4 → 8.2 |
| 化学镁离子 / 桌面 | 655.0 → 9.0 | 200.7 → 58.6 | 226.4 → 95.1 | 9.8 → 9.3 |
| 化学镁离子 / 触控横屏 | 655.0 → 9.0 | 212.5 → 58.5 | 241.3 → 99.6 | 11.0 → 8.7 |

- 化学保留原始粒子坐标计算，连续帧只更新移动粒子/连线属性；只有教学阶段改变时重新计算页内容。完整render从约655次减至9～10次，脚本与布局耗时下降。删除移动端完整render动画覆盖和footer MutationObserver。
- 物理完整render从78次减到6次（6次为翻页），播放阶段不重建模型。焦耳热温升与读数改为连续更新，CPU总开销反而上升，不能宣称该场景更省CPU。新增DOM节点计数中包含更新数字生成的文本节点，不等于重新创建整页或SVG。
- 物理旧版约45ms才更新画面一次；新版每次rAF局部更新。采样浏览器rAF间隔p95约5.7ms，反映本机headless调度，不是手机真机帧率，不据此宣称所有设备达到60fps。
- 按钮反馈本机均远小于100ms，优化前也没有复现老师所述的明显长停顿。这里测的是脚本点击后两次rAF完成时间，不是硬件触屏延迟或标准INP；网络、真机Safari和较慢设备的实际体验仍待复核。
- 滑块101次连续input只执行1次模型渲染，保留最终1.00/20Ω。不是降低整个动画帧数。
- 500次翻页压力检查后DOM稳定为79节点；强制GC后的堆在后几批约1.91、1.98、1.99、1.99MB，未观察到持续明显增长。有限场景不能证明不存在任何内存泄漏。

原始三轮JSON与Chrome可导入trace：`test-results/before-1-performance.json` 至 `after-3-performance.json`，以及同名前缀 `*-trace.json`。这些大文件只保留本地，不上传到公开仓库。

## PR #1 第二轮整改：焦耳热动画

第一轮局部更新每次 rAF 都改动两个温升柱、文本和读数；本机约每 5.7 ms 有一次 rAF，导致频繁布局和重绘。现在只把焦耳热场景的可视更新限制为间隔至少 33 ms（约 30 次/秒），教学状态仍按真实经过时间推进，阶段揭示和最终数值不跳过；其他动画保持原频率。

同一台 Windows / Chrome 156.0.8078.35 headless、1366×768，修改前后各独立运行三轮 `tests/performance.cjs`，每轮播放 3.6 秒并翻页六次，以下为中位数。测试内容、设备及浏览器配置相同，运行未并行争抢 CPU。

| 焦耳热场景 | 整改前 | 整改后 |
|---|---:|---:|
| 脚本耗时（CDP，ms） | 76.3 | 42.4 |
| 布局耗时（CDP，ms） | 111.3 | 45.9 |
| Paint 耗时（trace，ms） | 96.6 | 26.2 |
| 内容 DOM 变更记录 | 4044 | 1044 |
| 完整 render 次数 | 6 | 6 |
| 按钮到两次 rAF p95（ms） | 7.2 | 7.3 |

与最早 main 基线的焦耳热 48.0 ms 脚本、51.5 ms 布局相比，此次样本为 42.4 ms、45.9 ms，原回退在本机样本中消除。Paint 为 Chrome `devtools.timeline` 的渲染事件求和，与 CDP 脚本、布局指标来源不同；不把这些数字当作真实课堂投屏或 iPhone Safari 的帧率与电池耗用。原始 `review-before-{1..3}`、`review-after-{1..3}` JSON/trace 留在本地 `test-results/`，不上传大文件。较慢设备若仍出现卡顿，需在真机上复核更新频率。
